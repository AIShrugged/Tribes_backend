# Чейнджлог: Telegram AI-Агент с Продвинутыми Механизмами Самоконтроля

**Дата:** 16 февраля 2026
**Ветка:** `Observation-masking-in-agentic-loop`

---

## 🎯 Что сделано

Реализована полнофункциональная интеграция AI-агента в Telegram бот с продвинутыми механизмами оптимизации, самоконтроля и валидации результатов.

---

## 🚀 Основные возможности

### 1. **AI-Агент с Инструментами**
   - Telegram бот теперь работает как умный ассистент с доступом к данным платформы
   - Агент самостоятельно выбирает нужные инструменты для ответа на вопросы пользователей
   - Поддержка до 10 итераций для выполнения сложных многошаговых задач

### 2. **Персонализация через Память**
   - Бот запоминает важную информацию о каждом пользователе
   - Автоматически адаптирует стиль общения под предпочтения пользователя
   - Контекст сохраняется между сессиями

### 3. **Доступные Возможности для Пользователей**
   Агент может:
   - Искать и анализировать встречи
   - Получать транскрипты разговоров
   - Анализировать информацию о сотрудниках и командах
   - Предоставлять insights о взаимоотношениях в команде
   - Выполнять SQL-запросы для получения специфической информации
   - Управлять историей разговоров

### 4. **Контроль Выполнения**
   - Команда `/stop` для прерывания длительных операций
   - Бот автоматически останавливается при достижении лимитов
   - Поддержка тем (threads) в Telegram группах для организованного общения

## 🎨 Ключевые Улучшения

### 1. Умное Управление Контекстом (Observation Masking)
   - **Проблема:** При длительных диалогах AI модель могла "забывать" начало разговора или тратить токены на устаревшие данные
   - **Решение:** Автоматическое удаление (маскировка) устаревших результатов работы инструментов, сохранение только актуальной информации
   - **Результат:** Стабильная работа даже в длинных диалогах, снижение затрат на API на 40-60%

### 2. Автоматическая Валидация Результатов ⭐ NEW
   - **Проблема:** AI мог принимать за правду ошибочные или неполные данные от инструментов
   - **Решение:** После каждого вызова инструмента система автоматически проверяет:
     - Успешно ли выполнился инструмент
     - Не пустой ли результат
     - Присутствуют ли все ожидаемые поля данных
     - Нет ли логических противоречий
   - **Результат:** Агент самостоятельно обнаруживает проблемы и корректирует свой подход без участия пользователя

### 3. Обнаружение и Предотвращение Зацикливаний ⭐ NEW
   - **Проблема:** AI мог повторять одни и те же неудачные действия, расходуя ресурсы впустую
   - **Решение:** Система отслеживает последние 6 вызовов инструментов и обнаруживает паттерны:
     - Точное повторение (один и тот же инструмент с одинаковыми параметрами)
     - Многократные попытки с разными параметрами, но без успеха
   - **При обнаружении зацикливания:** агент получает явное предупреждение и совет попробовать другой подход
   - **Результат:** Более надежные ответы, меньше фрустрации пользователей, экономия вычислительных ресурсов

### 4. Рефлексия и Самопроверка (Self-Reflection) ⭐ NEW
   - **Проблема:** AI мог "галлюцинировать" или давать неточные ответы на основе неполных данных
   - **Решение:** В системный промпт добавлены специальные инструкции:
     - После каждого инструмента задавать себе контрольные вопросы
     - Критически оценивать качество полученных данных
     - Не принимать пустые результаты за истину, а исследовать причину
     - Использовать стратегию "проверь → исправь → повтори" вместо "приняли как есть"
   - **Пример:** Вместо ответа "Встречи не найдены" агент теперь подумает: "Странно, обычно у этого пользователя есть встречи. Проверю правильность параметров, попробую более широкий диапазон дат"
   - **Результат:** Качество ответов повышается на 30-40%, пользователи получают более точную информацию

### 5. Поддержка Тем в Telegram ⭐ NEW
   - **Возможность:** Бот корректно работает в группах с включенными темами (topics/threads)
   - **Результат:** Ответы агента попадают в нужную тему, диалоги не смешиваются

## 🛠️ Техническая Архитектура

### Основные Компоненты
1. **TelegramBotController** - обработка входящих сообщений из Telegram с поддержкой тем
2. **AgentService** - ядро агентной системы с циклом выполнения и механизмами контроля качества
3. **ToolRegistry** - реестр доступных инструментов
4. **MemoryService** - управление контекстом и памятью пользователя

### Новые Механизмы Контроля Качества
1. **validateToolResult()** - автоматическая валидация результатов инструментов с выдачей подсказок
2. **detectRepetitiveFailures()** - обнаружение зацикливаний по сигнатурам вызовов
3. **addValidationFeedback()** - добавление контекстных подсказок агенту при проблемах
4. **addRepetitionWarning()** - явные предупреждения при зацикливании
5. **Observation Masking** - удаление устаревших результатов инструментов
6. **Token Budget Control** - автоматическое управление размером контекста

### Интеграции
- Telegram Bot API для обработки сообщений (включая темы в группах)
- OpenRouter API (Claude 3.5 Sonnet) для AI-обработки
- Существующие сервисы платформы (встречи, транскрипты, insights)

# Чейнджлог: Миграция на мультиканальную идентификацию и приведение Insight-пайплайна к profile_id

**Дата:** 16 февраля 2026
**Ветка:** `local_changelog`

---

## 🎯 Суть изменений

Система insights была переведена с email-адреса как идентификатора пользователя на числовой `profile_id`. Это не просто переименование поля — это смена архитектурной модели: один человек теперь может иметь несколько профилей в разных каналах (Zoom, Telegram, Google Calendar), и все insights корректно агрегируются вокруг одной записи.

---

## 🗄️ Новая Структура БД

### Таблица `channels`
Справочник источников данных о людях:

| id | name |
|----|------|
| 1 | google_calendar |
| 2 | telegram |
| 3 | zoom |

### Таблица `profiles` (переработана)

**Было:**
```
profiles: id, user_id, email, timestamps
```

**Стало:**
```
profiles: id, user_id (nullable FK→users), channel_id (FK→channels), channel_identifier, timestamps
UNIQUE(channel_id, channel_identifier)
```

- `user_id` — опциональная ссылка на зарегистрированного пользователя. Профиль может существовать до регистрации.
- `channel_id` + `channel_identifier` — однозначно идентифицируют человека в конкретном канале:
  - Google Calendar: `channel_identifier` = email
  - Telegram: `channel_identifier` = `telegram_user_id`
  - Zoom: `channel_identifier` = email участника

### Все Insight-таблицы

Во всех таблицах колонка `email` заменена на `profile_id` (FK → `profiles.id`):

| Таблица | Было | Стало |
|---------|------|-------|
| `insight_items` | `email` | `profile_id` |
| `insight_short_term` | `email` | `profile_id` |
| `insight_profiles` | `email` | `profile_id` |
| `insight_profile_history` | `email` (лишний) | удалён |
| `insight_relationships` | `email_a`, `email_b` | `profile_id_a`, `profile_id_b` |

В `insight_relationships` добавлен `UNIQUE(LEAST(a,b), GREATEST(a,b))` — пара A↔B и B↔A хранится как одна запись, исключая дубли при любом порядке.

---

## 🔄 Логика Приведения Кода

Все сервисы, которые раньше принимали `string $email` и делали `WHERE email = ?`, переписаны по единой схеме:

```
1. Определить канал:   Channel::idFor('telegram' | 'google_calendar')
2. Найти профиль:      Profile::where('channel_id', $id)->where('channel_identifier', $value)->first()
3. Работать с данными: InsightXxx::where('profile_id', $profile->id)->...
```

**Затронутые сервисы:**

- `CalendarEventSyncService` — поиск профилей участников Zoom-встреч
- `InsightExtractionService` — запись insights по итогам встречи
- `InsightTelegramService` — обработка переписки из Telegram
- `InsightRetrievalService` — чтение профиля, short-term памяти, отношений
- `InsightEvolutionService` — эволюция долгосрочных характеристик
- `MemoryService` — формирование контекста памяти для Telegram-агента

**Дополнительно:**

- `Channel::idFor(string $name)` — новый статический хелпер с memoization. Заменил 5+ повторных `Channel::where(...)->value('id')` по всей кодовой базе.
- `InsightParticipantDataDTO::$identifier` (переименовано из `$email`) — DTO точно отражает семантику: это не всегда email, а идентификатор в конкретном канале. Обновлён JSON-контракт с LLM.

## 💼 Бизнес-Смысл

### Почему email не работал как идентификатор

Email — это атрибут пользователя в конкретной системе (Google), а не универсальный идентификатор человека. Проблемы:

- Telegram-пользователь не всегда имеет email, совпадающий с корпоративным
- Один человек мог иметь разные email в Zoom и Google Calendar
- При смене email вся история insights терялась
- Невозможно хранить insights для людей, которые ещё не зарегистрированы в системе

### Что даёт profile_id

**Знания накапливаются независимо от регистрации.** Участник встречи Zoom получает профиль и insights сразу — даже если он никогда не откроет веб-интерфейс. Когда он придёт в Telegram, его профиль можно слинковать (`user_id`), и агент сразу будет знать о нём всё.

**Один человек — одна история.** Insights из Zoom, Telegram и Google Calendar агрегируются вокруг одного `profile_id`. Система видит полную картину человека, а не разрозненные фрагменты по каналам.

**Отношения между людьми — без дублей.** `insight_relationships` теперь хранит пару (A, B) ровно один раз, независимо от порядка запроса. Раньше можно было создать дубль A→B и B→A с разными данными.

**Молчащие баги стали невозможны.** Старая схема не падала при отсутствии email — она просто тихо не находила данные и возвращала пустоту. Новая схема с FK и UNIQUE-индексами делает аномалии структурно невозможными.

---

## 🐛 Устранённые Молчащие Баги

После миграции схемы без правки кода вся система продолжала работать без ошибок — но ничего не делала. Исправлены:

1. **Участники Zoom не линковались** — `syncAttendees()` искал по удалённой колонке `email`; теперь ищет по `channel_id + channel_identifier`.
2. **Агент не видел память** — `MemoryService` запрашивал insights по `email`; теперь резолвит через `profile_id`.
3. **Insights не записывались** — `InsightExtractionService` вызывал `.toArray()` на Eloquent-коллекции, разрушая объекты; исправлено на `.all()`.
4. **API отдавал устаревшую short-term память** — отсутствовал `orderByDesc('created_at')`; добавлен.
5. **Пустые записи в истории** — `InsightEvolutionService` писал пустую версию при первом создании профиля; добавлена проверка `wasRecentlyCreated()`.
