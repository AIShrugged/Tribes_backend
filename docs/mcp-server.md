# MCP Server — Tribes

## Общее

**Сервер:** `Tribes` (`App\Mcp\Servers\HrServer`)
**Версия:** 1.0.0
**Описание:** HR-система Tribes: инсайты сотрудников, профили, история, встречи, фолоапы, задачи, команды, связи между людьми.

### Подключение

```
GET|POST /mcp
Authorization: Bearer <sanctum-token>
```

Аутентификация через Laravel Sanctum (bearer token). Протокол: [MCP (Model Context Protocol)](https://modelcontextprotocol.io/).

---

## Доступные инструменты (14 тулов)

### 1. `get_user_info`

Найти и получить подробную информацию о пользователе по ID, email или имени.

**Возвращает:** имя, email, профили (с `profile_id` по каждому каналу), организации, команды, роль.

> `profile_id` из ответа используется в тулах `get_user_insights`, `get_extracted_facts`, `get_insight_profile_history`, `get_tasks`.

**Параметры:**

| Параметр  | Тип     | Обязательный | Описание |
|-----------|---------|:------------:|----------|
| `user_id` | integer | Нет          | ID пользователя (точное совпадение) |
| `email`   | string  | Нет          | Email пользователя (точное совпадение) |
| `name`    | string  | Нет          | Полное или частичное имя (нечувствительно к регистру). Может вернуть несколько совпадений. |

Должен быть передан хотя бы один из параметров.

---

### 2. `get_user_insights`

Получить полный инсайт-профиль пользователя.

**Возвращает:** психологический профиль, стиль коммуникации, паттерны работы, сильные стороны, зоны роста, цели/мотивы, актуальный краткосрочный контекст, связи с другими людьми.

> Рекомендуется сначала вызвать `get_user_info` для получения `profile_id`.

**Параметры:**

| Параметр     | Тип     | Обязательный | Описание |
|--------------|---------|:------------:|----------|
| `profile_id` | integer | Нет          | **Предпочтительный.** `profile_id` из ответа `get_user_info` |
| `user_id`    | integer | Нет          | Использовать только если `profile_id` недоступен |

Должен быть передан хотя бы один из параметров.

---

### 3. `get_user_short_term_memory`

Получить краткосрочный контекст о пользователе.

**Возвращает:** временные данные — текущие проекты, недавние решения, эмоциональное состояние, актуальные знания. Контекст имеет срок жизни.

**Параметры:**

| Параметр  | Тип     | Обязательный | Описание |
|-----------|---------|:------------:|----------|
| `user_id` | integer | Нет          | ID пользователя |
| `email`   | string  | Нет          | Email пользователя |

Должен быть передан хотя бы один из параметров.

---

### 4. `get_extracted_facts`

Получить сырые факты об участнике, извлечённые AI из конкретных источников (транскрипты встреч или Telegram-чаты).

**Возвращает:** факты с оценкой достоверности, сгруппированные по источнику и категории.

> Использовать, когда нужны факты из конкретного источника (например, «что мы узнали об Иване на пятничной встрече»). Для агрегированного долгосрочного профиля — `get_user_insights`.

**Параметры:**

| Параметр      | Тип     | Обязательный | Описание |
|---------------|---------|:------------:|----------|
| `profile_id`  | integer | Да           | `profile_id` из `get_user_info` |
| `source_type` | string  | Нет          | Тип источника: `transcript` (встречи) или `telegram` (Telegram-чаты) |
| `source_id`   | integer | Нет          | Только для `source_type=transcript`. ID события календаря (`calendar_event_id`). Для Telegram не используется. |
| `category`    | string  | Нет          | Категория фактов: `communication_style`, `work_patterns`, `strengths`, `development_areas`, `goals_motivations`, `psychological_profile` |

---

### 5. `get_insight_profile_history`

Получить историю версий инсайт-профиля пользователя — как профиль менялся со временем.

**Возвращает:** хронологические снимки (версии) профиля с временными метками.

> Использовать при вопросах о динамике, изменениях или эволюции поведения, навыков или стиля коммуникации человека.

**Параметры:**

| Параметр     | Тип     | Обязательный | Описание |
|--------------|---------|:------------:|----------|
| `profile_id` | integer | Да           | `profile_id` из `get_user_info` |
| `category`   | string  | Нет          | Фильтр по категории: `communication_style`, `work_patterns`, `strengths`, `development_areas`, `goals_motivations`, `psychological_profile` |
| `limit`      | integer | Нет          | Максимальное количество записей (по умолчанию 10, максимум 50) |

---

### 6. `get_relationship_insight`

Получить динамику отношений между двумя людьми.

**Возвращает:** тип отношений (collaborative, conflicting, hierarchical, neutral), динамику взаимодействия, количество взаимодействий.

**Параметры:**

| Параметр    | Тип     | Обязательный | Описание |
|-------------|---------|:------------:|----------|
| `email_a`   | string  | Нет          | Email первого человека |
| `email_b`   | string  | Нет          | Email второго человека |
| `user_id_a` | integer | Нет          | User ID первого человека (альтернатива `email_a`) |
| `user_id_b` | integer | Нет          | User ID второго человека (альтернатива `email_b`) |

Для каждого участника нужен email или user_id.

---

### 7. `get_team_members`

Получить список всех участников команды.

**Возвращает:** информацию об участниках (id, имя, email), данные о команде и организации.

**Параметры:**

| Параметр    | Тип     | Обязательный | Описание |
|-------------|---------|:------------:|----------|
| `team_id`   | integer | Нет          | ID команды |
| `team_name` | string  | Нет          | Название команды (частичное совпадение, нечувствительно к регистру) |

Должен быть передан хотя бы один из параметров.

---

### 8. `search_meetings`

Поиск встреч/событий календаря по названию, диапазону дат, имени участника или участию пользователя.

**Возвращает:** список совпадающих событий, отсортированных хронологически (от старых к новым), с именами участников.

**Параметры:**

| Параметр           | Тип     | Обязательный | Описание |
|--------------------|---------|:------------:|----------|
| `query`            | string  | Нет          | Поисковый запрос по названию встречи (частичное совпадение, без учёта регистра) |
| `user_id`          | integer | Нет          | Фильтр: встречи, в которых участвовал этот пользователь |
| `participant_name` | string  | Нет          | Фильтр по имени участника (частичное совпадение) |
| `start_date`       | string  | Нет          | Встречи, начавшиеся не раньше этой даты. Форматы: `YYYY-MM-DD`, `YYYY-MM-DD HH:MM:SS`, ISO 8601 |
| `end_date`         | string  | Нет          | Встречи, начавшиеся не позже этой даты (конец дня, если указана только дата) |
| `limit`            | integer | Нет          | Максимум результатов (по умолчанию 10, максимум 50) |

> Для поиска встреч за конкретный день передайте одинаковые значения в `start_date` и `end_date`.

---

### 9. `get_followup`

Получить AI-сгенерированные оценки (фолоапы) по итогам встречи.

**Возвращает:** структурированную оценку каждого участника по методологии (например, DISC, 360-review): id, пользователь, команда, методология, статус, текст оценки.

**Параметры:**

| Параметр            | Тип     | Обязательный | Описание |
|---------------------|---------|:------------:|----------|
| `calendar_event_id` | integer | Да           | ID события календаря (встречи) |
| `user_id`           | integer | Нет          | Фильтр по конкретному пользователю |
| `status`            | string  | Нет          | Фильтр по статусу: `in_progress`, `done`, `failed` |

---

### 10. `get_meeting_summary`

Получить AI-сгенерированное резюме встречи.

**Возвращает:** общий текст резюме, ключевые тезисы, принятые решения, участников, дату и время встречи.

> Быстрее и структурированнее, чем `get_transcript`. Использовать при вопросах «что обсуждалось» или «что было решено».

**Параметры:**

| Параметр            | Тип     | Обязательный | Описание |
|---------------------|---------|:------------:|----------|
| `calendar_event_id` | integer | Да           | ID события календаря (встречи) |

---

### 11. `get_tasks`

Получить задачи и action items.

**Возвращает:** список задач с заголовком, описанием, исполнителем, сроком, статусом и привязкой к источнику.

> Использовать только когда пользователь явно спрашивает о задачах или поручениях. При вопросах «что обсуждалось на встрече» — использовать `get_meeting_summary`.

**Параметры:**

| Параметр            | Тип     | Обязательный | Описание |
|---------------------|---------|:------------:|----------|
| `calendar_event_id` | integer | Нет          | Фильтр: задачи, привязанные к конкретной встрече |
| `profile_id`        | integer | Нет          | Фильтр: задачи, назначенные конкретному человеку |
| `status`            | string  | Нет          | Фильтр по статусу: `open`, `in_progress`, `done`, `cancelled` |
| `due_before`        | string  | Нет          | Задачи со сроком до указанной даты (`YYYY-MM-DD`) |
| `due_after`         | string  | Нет          | Задачи со сроком после указанной даты (`YYYY-MM-DD`) |

Если параметры не переданы — возвращаются все задачи.

---

### 12. `create_task`

Создать новую задачу.

**Возвращает:** созданную задачу с присвоенным ID.

> Можно привязать к событию календаря, сообщению в чате или сообщению в Telegram.

**Параметры:**

| Параметр        | Тип     | Обязательный | Описание |
|-----------------|---------|:------------:|----------|
| `title`         | string  | Да           | Краткое название задачи |
| `description`   | string  | Нет          | Подробное описание |
| `assignee_name` | string  | Нет          | Полное имя ответственного |
| `profile_id`    | integer | Нет          | Profile ID исполнителя (из системы) |
| `due_date`      | string  | Нет          | Срок выполнения (`YYYY-MM-DD`) |
| `taskable_type` | string  | Нет          | Тип источника: `calendar_event`, `chat_message`, `telegram_chat_message` |
| `taskable_id`   | integer | Нет          | ID источника — обязателен при указании `taskable_type` |

---

### 13. `update_task_status`

Обновить статус существующей задачи.

**Возвращает:** id задачи, заголовок, старый и новый статус.

**Параметры:**

| Параметр  | Тип     | Обязательный | Описание |
|-----------|---------|:------------:|----------|
| `task_id` | integer | Да           | ID задачи |
| `status`  | string  | Да           | Новый статус: `open`, `in_progress`, `done`, `cancelled` |

---

### 14. `get_transcript`

⚠️ **Дорогостоящая операция — использовать только в крайнем случае.**

Получить и проанализировать полный транскрипт встречи.

**Возвращает:** транскрипт в текстовом виде или AI-анализ (если транскрипт большой или задан вопрос).

> Использовать только если: (1) `get_meeting_summary` недостаточно, (2) пользователь явно запрашивает дословный разговор, (3) нужна проверка точных цитат. **Перед вызовом необходимо спросить у пользователя подтверждение.**

**Параметры:**

| Параметр            | Тип     | Обязательный | Описание |
|---------------------|---------|:------------:|----------|
| `calendar_event_id` | integer | Да           | ID события календаря |
| `user_confirmed`    | boolean | Да           | `true` только после явного согласия пользователя на доступ к транскрипту |
| `question`          | string  | Нет          | Вопрос к транскрипту (например: «Какие решения были приняты?», «Что сказал Иван о проекте?»). При отсутствии — общее резюме. |

## Типовые цепочки вызовов

### Получить инсайт-профиль сотрудника
```
get_user_info(name="Иван Петров")
  → get_user_insights(profile_id=<из ответа>)
```

### Получить факты из конкретной встречи
```
get_user_info(name="Мария")
  → search_meetings(query="ретроспектива", start_date="2026-02-01")
  → get_extracted_facts(profile_id=<из user_info>, source_type="transcript", source_id=<calendar_event_id>)
```

### Задачи по встрече
```
search_meetings(query="планирование")
  → get_tasks(calendar_event_id=<id>)
  → update_task_status(task_id=<id>, status="done")
```

### Динамика отношений
```
get_user_info(name="Алексей")  → получить email_a
get_user_info(name="Екатерина") → получить email_b
  → get_relationship_insight(email_a=..., email_b=...)
```
